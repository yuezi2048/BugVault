红色边界：第 7 到 12 步都在 asyncio.create_task 里。它没有任务队列、没有完成回执（失败只 logger.exception）。 进程在 archive 写盘后、向量写库前中断，就会出现 「archive 已写，向量未入库」：文件在，但 retrieve_* 检索不到。 改进方向：外置任务队列 + 完成回执 + 启动时对 archive 与索引做对账。

红色边界与落差（以代码为准）

  1. 边界后台任务无队列、无回执。 asyncio.create_task(_persist_record_in_background) 是进程内任务；失败只 logger.exception。进程中断可能形成「archive 已写，向量未入库」，该记录检索不到。 tools.py:448 :460 :464 :466；事实卡 resume/active/bugvault-project-fact-card.md §7 第 1 条
  2. 落差archive 失败仍继续索引，与域模型不一致。 代码把归档异常记为 non-fatal（logger.exception("Failed to archive ...")）后照常返回非 draft 记录，后台仍会写向量；但 CONTEXT.md 的 «Record establishment» 说「校验通过且 Archive 成功后才成为正式记忆」。以代码为准：当前 archive 失败不阻断索引。 persistence_svc.py:152 :154 :156；CONTEXT.md «Record establishment»
  3. 落差draft 追问与 3 轮上限「定义未接线」。 draft 只返回缺字段清单（tools.py:488），不含追问提示。追问文案 suggest_probe_questions 与 suggest_convention_probe_questions 在整个 src/ 内除定义处外无调用；其中「每轮最多 3 问」由切片 suggestions[:3] 实现。 「最多 3 轮」由 MAX_PROBE_ROUNDS = 3 与 probe_round_exhausted / increment_probe 表达，但同样无调用；_probe_rounds 是 Pydantic 私有属性，随实例创建重置且不落库，ConventionRecord 无轮次概念。 ingestion_svc.py:21 :50 :67 :92；bug_record.py:77 :102 :105；tools.py:484 — 运行期是否另有接线：待核验
  4. 边界关闭异步开关时没有同步兜底。 enable_async_embedding=false 时 _handle_save_record 不调度后台任务，也不会同步写 LanceDB，结果是「只归档、不索引」。默认值为 True。 tools.py:442 :445；config.py:47；运行期实际环境取值：待核验
  5. 边界图叠加层只写未查。 保存时写节点与边，但检索链路不消费任何图遍历函数；ADR-002 Phase 3 才计划接入。 graph_db.py:371 :404；无消费点（src/ 全仓 grep find_*）；adr-002-graph-database-overlay.md:165
