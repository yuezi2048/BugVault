Recall@5 的分子分母与计算落点

函数 compute_recall(retrieved_ids, relevant_ids, k) 落在 benchmark_retrieval.py:62：分子 hits = 前 k 条结果中 record_id 命中 ground-truth 相关集合的条数（:65）；分母 len(relevant_ids) = 该查询的相关文档总数（:66）——分母是相关文档数，不是 k；无相关文档时直接返回 0.0（:63–64），所以 No-Answer 场景的 Recall 全部记 0。5 Recall@1/3/5 分别以 k=1/3/5 调用（:323 / :326 / :329）；MRR 在 compute_mrr（:70），NDCG@5 在 compute_ndcg（:80）；延迟用 time.perf_counter() 差值（:106 / :109 / :132 / :166）。6

实测两条管线均 0%：Vector-only 0.00%，平均仍返回 4.57 条；Hybrid 0.00%，平均仍返回 5.00 条。判定口径 accuracy()：只有返回 0 条才算拒答成功（benchmark_retrieval.py:352）——本次没有任何一条 No-Answer 查询返回空结果。10

红色报告自相矛盾：核心结论第 4 条 vs 实测 0%

report.md 核心结论第 4 条写「No-Answer 拒答可靠：Full Pipeline 在面对无关查询时能有效返回空结果」，与同文件 No-Answer 表的 0% 拒答率直接冲突；且该结论点名 Full Pipeline，而本次运行根本没有 Full 行（--skip-ce 未跑 CE），结论既无数据支撑又指错管线。该条应标为无效陈述。11

归因无 query 级相关性阈值，无拒答策略

  • 唯一的「相关性门槛」是 rerank() 里单文档的 min_semantic_score=0.50（retrieval_svc.py:419；config.py:29），它是逐条丢弃低分文档，不是「整条查询判定无答案」的拒答。
  • hybrid 路径在融合后主动 pop("_distance")（benchmark_retrieval.py:130），rerank() 走 _rrf_score 分支（retrieval_svc.py:422–424），阈值完全不生效，必然凑满 top-5 → 平均返回 5.00。
  • 结论：当前检索没有空结果/弃答分支，No-Answer 场景只能靠「碰巧没有候选」，所以 0% 是结构性而非偶然。12
图③附 LLM-as-Judge：策略，双重降级与成本边界默认关闭src/bugvault/services/rag_evaluator_svc.py · config.py

评测是检索之后的辅助评分步骤，不是检索的一部分；失败只丢评分，不阻断结果返回。

默认开关enable_rag_eval=False（config.py:50）；关闭或未配 API key 时 evaluate() 直接返回空结果（rag_evaluator_svc.py:568–569）13 策略选择eval_depth 运行时选："simple"（整体打分）或 "claim_level"（声明提取 + 逐条验证）——RAGEvaluator.evaluate（:550），Simple 类 :128，ClaimLevel 类 :298 评测范围eval_top_k=3（config.py:54），只评前 3 条检索结果
降1配额超限 → simple：claim_level 计数达到 max_claim_evals_per_session=10（config.py:64）即降级，标记 strategy_used="simple"（rag_evaluator_svc.py:593–601）。
降2异常 → simple fallback：claim_level 调用中任意异常（JSON 解析，超时，API 失败）被捕获，降级到 simple，标记 strategy_used="simple (fallback_from_error)"，调用方看不到异常（:605–616）。14
成本claim_level 约 1.6k tokens/次，耗时远大于检索（检索延迟仅 0.03–0.05s）。token 估算来自设计文档 codex-docs/refer/设计/evaluation-strategy.md（simple ~300，claim_level ~1500）；代码只固定 max_tokens（simple 256 于 :236，claim 2048 于 :440），实际 token 与耗时待核验。15

落差计数器是进程内全局类变量，不是会话级

RAGEvaluator._claim_counter 是类变量（rag_evaluator_svc.py:528，注释写作「session-scoped, never reset」，config.py:64 也写「session-wide cap」），但类变量在进程内所有会话，所有客户端间共享，不会随会话重置。所以真实口径是进程生命周期内全局熔断，不能说成「会话级配额」。14
