步骤说明

  1. 1query 进入：客户端调用 retrieve_bug_experience，query 必填，target_tech_stack / target_project_name 可选（mcp_tools/tools.py:44,86,527–541）。handler 经 _retrieve_records（tools.py:621–630）把同步检索提交到共享线程池 run_in_executor，避免阻塞 stdio 事件循环。空 query 在 retrieve() 直接返回错误文案（retrieval_svc.py:68–71）。
  2. 2生成 embedding + 元数据过滤：rerank_limit = settings.top_k * 4（retrieval_svc.py:78）；build_filter_clause（:260）对 tech_stack / project_name 生成 LOWER(...) LIKE '%值%'，_record_type_filter（:280）再拼 record_type='bug'。过滤值先过 sanitise_filter_value（:253）。_TECH_EXCLUSIONS（:248）为 java 追加 NOT LIKE '%javascript%'，消除 Java 与 JavaScript 歧义。随后 embedding_svc.generate_embedding(query)（:86，bge-small-zh-v1.5，512 维）。
  3. 3双路召回（各 top_k × 4）：在 bugvault_chunks 上做向量 ANN（search_chunks，lancedb_client.py:284）与 FTS BM25（search_chunks_fts，:253）；两路共用同一 filter_clause，即过滤条件同时下推到两路。两路各取 limit = 20（retrieval_svc.py:141–155），FTS 结果再过滤 _score > 0（:179）。
  4. 4排序层 ① RRF 融合：rrf_fusion(vec_results, fts_results, k=60)（retrieval_svc.py:326–383）。向量路按 _distance 升序、FTS 路按 _score 降序各自排名，累加 1/(k+rank)（:360,:366）。只用排名，不归一化余弦距离与 BM25 分数量纲，所以无需把两路分数调到同一尺度。k 默认 60（:329）。
  5. 5取每父记录最佳 chunk + 回捞完整记录：_map_chunks_to_parent_records（retrieval_svc.py:204–233）按 parent_id 分组，用 _chunk_score（:285）取每父最佳 chunk，再用其 parent_id（等于 record_id）集合调 fetch_records_by_ids（lancedb_client.py:324），SQL 为 record_id IN (...)（:342），从 bug_records 回查完整记录。为什么分块：整条长记录压成一个向量会稀释错误栈特征；子块聚焦命中、父文档回捞保证完整（bug_record.py:143–190）。
  6. 6排序层 ② 可选 Cross-Encoder 精排，返回 Top-K：先 rerank(records)（retrieval_svc.py:391）把 RRF 序（或纯向量语义分）叠加时间衰减，enable_recency_decay 默认 False（:430）；若 enable_reranker=True 再调 CrossEncoderReranker.rerank（reranker_svc.py:55）加 _ce_score 重排。最后 _to_records(ranked[:settings.top_k], record_type)（:112）返回 top_k 条。注意：第 4 步 RRF 与第 6 步 CE 是两段独立排序，不是一次打分。
