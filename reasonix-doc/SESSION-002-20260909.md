# SESSION-002: 2026-09-09 - 测试诊断与离线集成测试修复

> 状态：已完成代码改造；真实 LanceDB e2e 验证受当前本机环境阻塞

## 一、会话目标

处理 BugVault 测试运行中的以下问题：

- pytest 收集了 `refer/` 下无关的外部项目测试，导致大量报错。
- `tests/test_integration.py` 启动 MCP 服务耗时很长，随后失败。
- 失败信息只显示 MCP `Connection closed`，缺少服务端真实原因。

## 二、诊断结论

集成测试启动 `bugvault.main` 时，生产配置会初始化 FastEmbed：
`BAAI/bge-small-zh-v1.5`。本机模型缓存不完整，FastEmbed 尝试访问
Hugging Face；当前网络不可达，子进程在初始化阶段崩溃，客户端因此收到
`McpError: Connection closed`。

此外，保存工具会先返回成功，再后台异步写入 embedding、LanceDB 和 Graph。
测试立即检索存在时序竞争，可能在索引投影完成前得到空结果。项目上下文明确
规定向量和 Graph 投影是 eventually consistent。

原集成测试还默认使用 `~/.bugvault`，会污染用户数据并积累历史测试记录。

## 三、代码改动

### 3.1 pytest 收集范围

在 `pyproject.toml` 增加：

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
```

pytest 只收集项目自己的 `tests/`，避免执行 `refer/` 下的外部测试。

### 3.2 离线 MCP 测试服务

新增 `tests/e2e_server.py`：

- 保留真实 MCP stdio、工具注册、RecordPersistence、LanceDB 和 Retrieval 链路。
- 使用确定性的本地哈希向量替代 FastEmbed。
- 不改变生产入口 `src/bugvault/main.py` 的模型行为。

### 3.3 集成测试稳定性

更新 `tests/test_integration.py`：

- 使用 `tmp_path` 作为每个测试的数据根目录。
- 关闭 reranker、RAG evaluation、reflection tool 和 FTS 等非必要慢组件。
- 保存后轮询检索结果，最多等待 15 秒以覆盖异步索引投影。
- MCP 初始化增加 30 秒超时，避免服务启动失败时长时间无反馈。
- 使用相对仓库路径，不再依赖固定绝对路径。


## 七、后续建议

1. 在可用的 LanceDB 环境运行两个 e2e 用例。
2. 若 LanceDB 仍卡住，清理或迁移受影响的数据目录前先确认没有活动进程，
   并检查 LanceDB 与 Rust 依赖版本。
3. 为生产 FastEmbed 模型建立明确的预下载/离线缓存步骤，避免服务首次启动
