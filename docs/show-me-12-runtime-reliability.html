ThreadPoolExecutorbugvault-io

同步 LanceDB 与 ONNX 推理
  • 同步 LanceDB：向量 ANN、FTS(BM25)、upsert_record / upsert_chunks、回查父记录
  • ONNX 推理：embedding 批量编码、Cross-Encoder 精排
  • 本地 IO：写 Markdown 归档、Graph 投影
  • 反射工具：ReflectionService 同步调用（tools.py:364–370）
线程池参数
  • max_workers = settings.thread_pool_workers，默认 2（config.py:40；.env:37 该键被注释，默认生效）
  • thread_name_prefix = "bugvault-io"（main.py:43）
  • 并发上限 2；第 3 个并发阻塞活进入内部队列等待空闲线程。排队顺序由 CPython ThreadPoolExecutor 的 SimpleQueue 决定，顺序性待核验
  • 该 executor 为进程内共享单例：检索、保存校验、后台持久化、反射 争用同一 2 个线程，不是水平扩展
为什么阻塞 IO 不能留在事件循环：LanceDB 查询、ONNX 推理和文件写入都是同步阻塞调用。asyncio 事件循环是单线程的，一旦在协程里直接调用它们，整个循环会被占住，正在等待的 stdio 协议帧（含 initialize 握手与其他工具调用）都无法推进。把阻塞段用 run_in_executor 推给线程池后，事件循环只保留 await，可继续处理其他请求。

步骤说明（按左侧序号对照）

  1. 1进入事件循环：traceId + entry 日志。客户端调用 save_bug_experience（或 save_convention）进入 handle_call_tool（tools.py:306）。先 set_trace_id() 生成 12 位 hex trace 并写入 ContextVar（tools.py:310，logger.py:32，get_trace_id:42），再构造 AiCallLogEntry(event_type="entry") 写 JSONL 与 stderr 日志（tools.py:314–320）。
  2. 2跨边界① 保存校验：run_in_executor(prepare)。await loop.run_in_executor(executor, prepare, arguments)（tools.py:437–440）。prepare 是 persistence.prepare_bug / prepare_convention（tools.py:427–435）。线程内先 record_factory(**arguments) 做 Pydantic 校验，缺必填字段返回 PreparedRecord(is_draft=True)；校验通过后写 Markdown 归档，归档失败非致命（logger.exception("Failed to archive ...")，persistence_svc.py:139–155）。
  3. 3先返回「已保存」：调度后台，不 await。仅当 prepared.record 非空、非 draft、enable_async_embedding=True 且 embedding_svc is not None 时，调 asyncio.create_task(_persist_record_in_background(...))（tools.py:441–455），随后立即 return _present_save_outcome(prepared)（tools.py:457）。此时向量索引尚未写入。返回文案由 _present_save_outcome 生成：「... saved successfully」（tools.py:470–517）。
  4. 4跨边界③ 后台持久化：run_in_executor(persist)。后台协程 _persist_record_in_background 内 await loop.run_in_executor(executor, persistence.persist, record)（tools.py:460–463）。persist 先 embed(record) 得到父向量与 chunk 向量，触发 embedding 懒加载：_ensure_model() 双检锁（embedding_svc.py:67–80）后 _init_model() 加载 ONNX 并 list(self._model.embed(["warmup"])) 热启，避免首次真实推理吃 500ms+ 冷启（embedding_svc.py:46–65）。
  5. 5写库 + 图投影（可选）。线程内 upsert_record(table_row) 与 upsert_chunks(chunk_rows)，再 _project_graph（persistence_svc.py:114–120）。图投影异常被吞成 非致命（persistence_svc.py:158–165）；write_bug_graph_edges 内部在 graph_db is None 时直接返回。后台任务整体失败只 logger.exception，不反向失败本次调用（tools.py:464–468）。
  6. 6检索进入：跨边界② run_in_executor(retrieve)。retrieve_bug_experience(query) → _handle_retrieve（tools.py:518）→ _retrieve_records 内 await loop.run_in_executor(executor, retrieval.retrieve, request)（tools.py:621–630）。
  7. 7线程池内：双路召回 + RRF。RetrievalModule.retrieve（retrieval_svc.py:66）先 generate_embedding(query)，在 bugvault_chunks 做向量 ANN 与 FTS(BM25) 两路召回，rrf_fusion(k=60) 融合（retrieval_svc.py:87–99，326）。FTS 失败→vector-only（retrieval_svc.py:180–181，200–201）。
  8. 8Cross-Encoder 精排（可选）。enable_reranker=True 时 self._get_reranker() 取模块级单例并 rerank(query, ranked)（retrieval_svc.py:100–109，240–245）；get_reranker 懒加载，初始化失败返回 None（reranker_svc.py:18–33，88–94）。CE 失败→保留 RRF 序（retrieval_svc.py:108–109，reranker_svc.py:70–72）。
  9. 9可选 RAG 评测 → 返回文本。检索结果返回事件循环后，如 rag_evaluator.enabled 且 eval_depth != "none"，await rag_evaluator.evaluate(...) 追加评分（tools.py:556–572）；评测异常只跳过评分，结果照常返回（tools.py:573–575）。最后返回格式化文本。

为什么 embedding 必须懒加载：模型构造可能读本地 FastEmbed 缓存或尝试联网下载。若放在启动路径，initialize 握手会因缓存不全或断网而挂起；懒加载让 stdio 握手先完成，把加载错误留到真正调用工具时才抛出（embedding_svc.py:67–76 动机注释）。
